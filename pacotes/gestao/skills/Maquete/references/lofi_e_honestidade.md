# Por que lo-fi cinza (e por que isso é uma força, não uma limitação)

O protótipo da Maquete é de propósito **cinza, sem cor de marca, sem arte final**.
Isso não é preguiça — é uma técnica de design consagrada (baixa fidelidade / lo-fi).

## O que a baixa fidelidade compra
1. **A conversa certa.** Quando você mostra uma tela colorida e polida, o cliente
   comenta a cor do botão, a fonte, o logo. Quando você mostra um wireframe cinza,
   ele comenta o que importa nesta fase: "falta uma tela de confirmação", "e se o
   cliente não tiver e-mail?", "esse botão devia estar no topo". Estrutura e
   navegação primeiro; estética depois.
2. **Velocidade e coragem para mudar.** Ninguém tem medo de jogar fora um wireframe
   cinza. Uma tela bonita que levou horas, ninguém quer mexer — mesmo estando errada.
   Lo-fi mantém o desenho barato e, por isso, honesto.
3. **Expectativa correta.** O selo "rascunho navegável / não é a arte final" no
   protótipo evita que o cliente ache que o produto está pronto. A maquete é para
   DECIDIR, não para entregar.

## Honestidade do conteúdo
- **Nada de dado inventado.** Não escreva "João da Silva — R$ 1.240,00" se o dono não
  deu esses dados. Use rótulos genéricos ("[nome do cliente]", "[valor]") ou deixe os
  campos em branco (o motor já desenha inputs vazios listrados). Um número inventado
  vira decisão errada quando alguém acredita nele.
- **Placeholder é sinal, não defeito.** As áreas listradas e as linhas de tabela
  vazias mostram "aqui entra conteúdo real depois" — isso é informação, não falta.

## Quando subir a fidelidade
Só DEPOIS de o fluxo estar validado (o cliente navegou e aprovou a estrutura). Aí a
cor, a marca e a arte final entram — no build (Estaleiro/Claude Code) ou com um
designer. A Maquete entrega a forma certa; a beleza vem em cima de uma forma certa.
